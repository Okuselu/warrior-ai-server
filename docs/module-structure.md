# Warrior AI server — module structure

Domain layout inspired by `troott-api/`, sized for the MVP (no migrations, seeding, or legacy revamp machinery). Each module owns one slice of the data contract and follows the same five-file pattern:

```
src/modules/<domain>/
├── dtos/<domain>.dto.ts              # Request/response DTOs (lower camelCase wire fields)
├── models/<domain>.model.ts          # Mongoose schema + TypeScript record type
├── repository/<domain>.repository.ts # Data access only; constructors do no I/O
├── services/<domain>.service.ts      # Business logic; accepts (context, requestDTO), returns response DTO
└── routes/<domain>.routes.ts         # Express router: bind DTO -> call service -> sendResponse
```

Cross-cutting code lives in `src/common/` (`dtos`, `errors` via `utils/error.util.ts`, `factory`, `http`, `middleware`, `repository`, `utils`). Process bootstrap is split between `config/db.config` equivalents (`config/db.ts`, `config/env.ts`), `config/app.config.ts` (`createApplication()` + route registration), and `index.ts` (connect DB, listen, graceful shutdown).

## Request/response convention

- Handlers never write error bodies. Services throw `ErrorResponse` subclasses; `middleware/errorHandler.ts` writes the single envelope: `{ error, errors, data, message, status }`.
- Success uses `sendResponse()` and the same envelope with `error: false`.
- Context is the first service argument: `RequestContextDTO` populated by `request.middleware.ts` from `X-Request-ID`, `X-Correlation-ID`, `Accept-Language`, etc.
- List endpoints accept `page`, `limit`, `select`, `order`, `from`, `to` and return `count`, `total`, `pagination.next/prev` (`common/utils/pagination.util.ts`).
- IDs are UUIDv4 generated by the client for offline records (`common/utils/id.ts`). Timestamps are ISO 8601 UTC strings (`common/utils/date.ts`).
- Vocabularies and clinical codes live in `common/constants.ts`; display text for `en`/`yo`/`pcm` is kept out of code.

## Module map

| Module | Data contract entities | PRD features | HTTP surface (under `API_ROUTE`, default `/api/v1`) |
|---|---|---|---|
| `identity` | User, PatientProfile | F1 onboarding, caregiver profiles | `/identity/users`, `/identity/patients` |
| `consent` | ConsentRecord, CareCircleContact | F1 consent, F6 care circle | `/consent/consents`, `/consent/contacts` |
| `checkin` | CheckIn (+ same-day revisions) | F2 daily check-in, SMS fallback | `/checkins` |
| `risk` | RiskAssessment, RuleSet | F3 traffic light, F4 red-flag triage | `/risk/assessments`, `/risk/rules/active` |
| `medication` | MedicationSchedule, DoseLog | F5 reminders, adherence | `/medication/schedules`, `/medication/doses` |
| `crisis` | CrisisEvent | F8 crisis log and insights | `/crises` |
| `clinic` | Clinic, ShareRecord, ClinicianAnnotation | F7 summary, F10 care finder, F12 contact clinic, F13 dashboard | `/clinic/shares`, `/clinic/annotations`, `/clinic/dashboard/risk` |
| `community` | CommunityGroup, Member, Post, Report, restricted PseudonymMap | F11 moderated peer circle | `/community/groups`, `/community/posts`, `/community/reports` |
| `events` | Event envelope + idempotency log | §7 sync protocol | `/events` |
| `alerts` | AlertDelivery record | F6 care-circle alerts | `/alerts`, `/alerts/failures` |
| `audit` | AuditLog (append-only) | §4.13 / privacy access logging | `/audit` |

## Implementation status

- **Ready schemas/repositories**: all contract entities, with enum/range validation, append-only hooks for consent/audit, and an idempotent event ingest.
- **Working handlers**: registration, patient profiles, consent, check-ins, schedules/doses, crises, shares/annotations, community posts/reports, event ingest, audit log.
- **Explicit stubs (`501 NOT_IMPLEMENTED`)**: rule evaluation and RuleSet activation (clinical sign-off pending), clinician dashboard ranking, SMS/WhatsApp dispatch (provider pending). Auth, rate limiting, and admin second-approval remain out of this scaffold.

Security boundaries encoded in code: Class A fields are never written to audit logs; `PseudonymMapRepository` is the only path from a pseudonym to a user, and it is never injected into moderator-facing services.
